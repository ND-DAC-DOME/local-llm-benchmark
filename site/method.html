How it was measured

The test bed

One harness (bench.py) talks to each model through its server's OpenAI-compatible API, sends the same prompts, grades the answers automatically, and saves every prompt, reasoning trace, answer, verdict, token count and latency. Everything here is reproducible from the repository; the scripts that ran are in runs/.

Why these: GSM8K and HumanEval have known expected scores and validate the harness; MMLU-Pro, GPQA Diamond and LiveCodeBench have headroom for models of this class and cover knowledge, science and code. AIME was considered and dropped: vendors report 94–95% for these models. None is an agentic workflow. All three grading methods are automatic and objective (exact match, executed tests); no human or model judge.

The token budget

These are reasoning models: they generate thinking tokens before the answer, as many as they want. Every evaluation caps that, and so do the vendors (Qwen reports LiveCodeBench with up to 80k tokens). We used 12,288 tokens per answer for the first round and 32,768 for the second. An answer that hits the cap without a final answer counts as wrong, and is reported separately as "not finished". The cap turned out to be the variable that decides the ranking, so both budgets are shown wherever they exist.

Speed

  • Decode: one short prompt, 512 tokens, streaming, 3 sequential requests; tokens ÷ (time from first to last token); median.
  • Prefill: prompts of ~1k, ~4k and ~12k tokens with max_tokens=1; prompt tokens ÷ time to first token; 3 repetitions, each with a unique prefix so a prefix cache cannot serve a repeat; median.
  • Prefix cache: the same prompt sent twice; the second request's time and the server's hit counter tell whether the cache served it. Five usage patterns; the server checked idle before each call.
  • Token counts always come from the server's usage field, never estimated.

Corrections made along the way

  • HumanEval scorer: the first pass did not keep the problem's helper functions in scope; 4 Muse solutions failed with NameError. Fixed, and every saved answer re-graded. All later runs used the fixed scorer.
  • LiveCodeBench scorer: an injected from math import * shadowed the built-in pow(a, b, mod); programs now run exactly as written. And the judge environment: 23 Muse solutions used numba, which the real AtCoder judge provides; scores are reported both with the standard library only (strict) and with numpy/scipy/numba available (judge env, the headline). Saved answers were re-graded under both, nothing regenerated.
  • Every wrong answer of every run was classified (wrong / not finished / parser miss / harness error). Parser misses: zero in all runs.

What is and is not reproducible

  • Pinned: container images (by digest), Python packages, dataset revisions, model snapshots with file hashes, item samples (seed).
  • Not deterministic: sampling at temperature 1.0 and GPU kernels. The same Qwen3.8 checkpoint scored 74.5 / 77.0 / 76.0 on MMLU-Pro in three runs; read every difference against that ±1.5.
  • Repository: README.md (reproduction), results.md (full report), MODELS.md, docs/spark-measurements.md (the command behind every Spark number).
